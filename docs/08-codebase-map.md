## 2. Protected Core vs. Additive Modification Inventory

Per **RULES.md § 1**, agents must never replace or refactor protected core systems.

### Protected Core Files (Do NOT rewrite, replace, or bypass)
- `api/app/security.py`: Password hashing (`bcrypt`), JWT creation/validation (`PyJWT`), token secret keys.
- `api/app/api/app/access.py`: `decode_access_token`, `build_http_user_dependency`, audience validation (`JWT_AUDIENCE_APP`), and cookie inspection.
- `api/app/api/internal/access.py`: Staff gate dependency (`JWT_AUDIENCE_INTERNAL`, `user.is_admin` requirement).
- `api/app/database.py`: Async engine configuration, session lifecycle (`DBSession`).
- `app/src/lib/api-client.ts`: Custom Orval fetch mutator (`credentials: "include"`, `ApiError`).
- Client generation pipelines (`orval.config.ts` and `npm run generate`).

### Additive Files & Locations (Where we build)
- **New Models:** Defined in `api/app/models.py` or modular domain files imported into `models.py`.
- **New Migrations:** Generated via `uv run alembic revision --autogenerate`.
- **New Routers:** Registered additively in `api/app/api/app/router.py` (e.g., `orgs.py`, `teams.py`, `plans.py`, `ai.py`).
- **New Services:** Placed in `api/app/services/` following the existing `users.py` pattern.
- **New UI Routes:** Added in `app/src/routes/_main/` (plans, teams, settings) and `app/src/routes/` (signup, invite).
- **New Tests:** Created in `tests/api/app/` and `tests/api/internal/`.

## 3. End-to-End Request Lifecycles

### A. Authentication & Session Establishment (Existing Core)
1. Browser posts credentials to `POST /app/auth/login`.
2. Router calls `verify_password(login_data.password, user.password)`.
3. If valid, generates JWT with `aud="app"`.
4. Router sets `Set-Cookie: access_token=Bearer <token>; HttpOnly; SameSite=Lax; Path=/`.
5. Subsequent requests send cookie automatically (`credentials: "include"` in `api-client.ts`).
6. `CurrentUser` dependency extracts cookie, decodes token, verifies `aud=="app"`, and queries `User` from PostgreSQL.

### B. Sign-Up & Organization Onboarding (New Flow)
1. Unauthenticated user visits `/signup` on `app/`.
2. Submits email, password, name, and either organization name or invite token.
3. Calls `POST /app/auth/signup`.
4. Service hashes password with existing `get_password_hash()`, inserts `User`, creates `Organization`, and inserts `Membership` with `org_role="owner"`.
5. Sets `access_token` cookie and returns user profile. User is immediately redirected to `/dashboard`.

### C. Weekly Plan Creation & Lifecycle Flow
1. Member navigates to `/plan` in `app/`.
2. Query fetches current week's plan (`GET /app/orgs/{org_id}/plans/current`).
3. If no plan exists, member drafts Main Task, Sub-goals, and GTM goals.
4. Member clicks "Review with AI": calls `POST /app/orgs/{org_id}/plans/review`.
5. Pydantic AI agent critiques the draft, returning structured `PlanReviewResult` (issues + suggested rewrites).
6. Member accepts suggestions with one click (updating form state), then clicks "Submit for Approval".
7. Plan status transitions from `"draft"` to `"submitted"`.
8. Team lead logs in, reviews the plan on the team week dashboard, and clicks "Approve" (`POST /app/orgs/{org_id}/plans/{id}/approve`) or "Send Back" with comment.

### D. Multi-Tenant Isolation Enforcement
1. Every customer request hits a route with `tenant: TenantContext = Depends(get_tenant_context)`.
2. Dependency executes:
   - Fetches target `Organization` from database.
   - If `org.is_suspended == True`, raises `403 FORBIDDEN` (`ORGANIZATION_SUSPENDED`).
   - Queries `Membership` where `organization_id == target_id` and `user_id == current_user.id`.
   - If no membership exists, raises `404 NOT FOUND` (never 403, preventing ID discovery).
3. All queries execute with explicit `where(Entity.organization_id == tenant.org.id)`.

### E. Internal Staff Operations & Telemetry
1. Platform staff log in to `/internal` receiving JWT tokens minted with `aud="internal"` and stored in `internal_access_token` HttpOnly cookie.
2. Every request on `/internal` is guarded by `CurrentInternalUser` (`user.is_admin == True`).
3. Endpoints in `api/app/api/internal/routers/`:
   - `orgs.py`: `GET /internal/orgs` (list with search, counts, last active), `GET /internal/orgs/{id}`, `POST /internal/orgs/{id}/suspend`, `POST /internal/orgs/{id}/reinstate`.
   - `users.py`: `GET /internal/users` (search by email/name, includes organization memberships), `POST /internal/users/{id}/deactivate`, `POST /internal/users/{id}/reactivate`.
   - `ai_usage.py`: `GET /internal/ai-usage` (platform totals, per-org aggregates, and recent call logs from `AICallLog`).
4. In accordance with Decision 1, no endpoint in `/internal` exposes customer plan text or task details.
